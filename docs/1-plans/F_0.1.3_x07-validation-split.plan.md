## Overview

X07 as inherited bundles certificate validation that requires X04's
never-produced full-scope certificate with validation that is executable
today. This plan splits the ticket (precedent: the X06/X07 split), then
closes the executable half: the certificate machinery's ~30 unexercised
failure branches get negative tests, the verifiers get bounded
deserialization, the repository gets its first public copy-audit harness
(with two approved claim-narrowing fixes), and the whole chain plus read-only
live smoke is run to close the ticket honestly.

## Problem Statement

The survey found: zero negative tests across the scope module's four throw
paths and both verifier scripts' ~30 fail branches; ~40 raw `JSON.parse`
calls in scripts with no size/depth caps; no copy-audit harness despite the
charter's claims discipline; one unqualified absolute claim in the UI
("All legal teams checked") and generated caveat text that is never
rendered; and no live-site probe despite the ticket's live-smoke clause.

## Solution Architecture

Four phases. Phase 1 restructures the epic (documents only). Phase 2 adds
negative-path regressions: core-level vitest tests where the logic lives in
core (scope throws, coverage stale detectors, contract literals), and a
script-level mutation-rejection runner for the `.mjs` verifiers (which
vitest does not cover), plus a shared bounded JSON reader. Phase 3 builds
the copy-audit harness with an explicit disposition ledger (so non-technical
uses of "exact"/"score" are classified, not ignored) and applies the two
approved copy corrections. Phase 4 runs everything, closes X07 from
evidence, and releases 0.1.3 locally. Implementation is delegated to Codex
per the standing D-2 lane; batches are reviewed and staged as in the
previous iteration.

## Technical Considerations

- **Pattern Usage**: negative tests mirror `native-guide-schema.test.ts`'s
  refinement-violation style; bounded reader mirrors
  `team-roster-storage.ts`'s allow-list discipline; audit gate mirrors the
  `absoluteScoreAvailable` precedent (`validate-data.ts:58-60`).
- **Determinism & Evidence**: the copy-audit artifact follows the
  `data/native/*-v1.json` + schemaVersion + stable-digest convention with
  the undefined-skipping canonicalize.
- **Claim Boundaries**: copy fixes narrow claims only; the audit ledger
  documents every allowed occurrence's justification; HC-1 flags untouched.
- **Parity Cost Awareness**: no evaluator/kernel/accumulator semantic
  changes anywhere in this plan → no parity re-execution obligated. Any
  additive export needed for scope-validation tests follows the D-6
  digest-gate pattern (`optimizer:parity:bulk:rehash` must stay `320da206…`).
- **Edge Cases**: audit false-positive class ("exact card", "score a song");
  e2e copy assertions; verifier valid-path byte-identity after the bounded
  reader; Windows path handling in the temp-mutation runner.
