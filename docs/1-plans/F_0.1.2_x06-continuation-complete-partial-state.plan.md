# X06 Takeover: Audit + Continuation-Complete Fixed-Leader Partial State

## Mission Charter

**Core Directive**: Take over the uncommitted X06 exact-optimizer work,
independently audit it against its own claims, then design and prove a
continuation-complete fixed-Leader partial-state schema and exhaustively
validate every legal suffix on a reduced roster — granting dominance
pruning/timing credit only if the proof holds, and otherwise recording the
honest measured blocker with `attempted:false` preserved.

**Hard Constraints** (inviolable):

  all existing edits; never `git reset --hard` or destructive checkout.
- **HC-2**: MUST keep `certificateEligible=false` and `fullRunAuthorized=false`
  in every artifact touched by this work.

  settings or repository visibility. Local checkpoint commits at verified

  improve runtime.

## Overview

The previous agent left X06 (guarded bulk accumulation + dominance
feasibility) at 5/6 criteria with ~1,300 lines of uncommitted changes plus 15
untracked files. This plan takes over that work in two movements: first an
independent audit of the uncommitted implementation against its own recorded
evidence (trust nothing from prior reports), then the one remaining
scientific task — designing a fixed-Leader partial-state schema proven
sufficient to resume every legal suffix exactly, validated by exhaustive
reduced-roster enumeration before any dominance rule may ever earn credit.

## Problem Statement

Dominance pruning is the only remaining idea with the potential to close the
~45× gap between the measured full-scope cost (36,624 raw core-hours) and the
800 core-hour gate — but Phase 7 was formally killed before pilot because no
partial-state key was proven continuation-complete. An unsound key would
silently produce a wrong "exact" winner, which this project treats as worse
than no speedup. The kill artifact records exactly four missing proofs
(Leader-specific continuation; complete branch identity; enclosure/source-
order preservation; tie-key/finalist promotion). This plan supplies either
those proofs or an honest, concrete counterexample.

## Solution Architecture

Two sequential phases with a checkpoint commit between:

1. **Takeover audit (read/verify, no semantic edits)** — inspect the
   accumulated diff from `c0267720` and all untracked files across the six
   audit surfaces; run the focused verification set; write the audit CR. Any
   defect found becomes a logged finding: minor/documentation issues fixed in
   place, semantic defects escalated to the user before touching evaluator
   code (they would obligate full parity reruns).
2. **Partial-state proof (design → encode → exhaust)** — write the schema and
   sufficiency argument as a document first (design-before-code, matching the
   dominance kill criterion's own demand); then implement the schema and a
   suffix-resumption harness in core; then run exhaustive reduced-roster
   validation where the harness's resumed results are compared against the
   reference evaluator's full-formation results for every legal suffix of
   every represented partial state. Sufficiency is claimed only over
   dimensions the enumeration actually exercised.

Implementation is delegated to Codex (per Decision D-2) with Claude
supervising, verifying evidence, and running the review loop.

## Technical Considerations

- **Pattern Usage**: TypeScript reference evaluator stays authoritative; the
  harness compares against it, never replaces it. Evidence artifacts follow
  the `data/native/*-v1.json` + schemaVersion + stable-digest pattern.
- **Determinism & Evidence**: fixed iteration order over Leaders/charts/
  suffixes; digest excludes timestamps; rerun reproducibility is part of
  DoD-5.
- **Exact Arithmetic Discipline**: resumption must reproduce ordered binary64
  results bit-identically — mergeability requires identical accumulator
  source-order position and enclosure endpoints; no interval widening tricks.
- **Claim Boundaries**: success here proves continuation-completeness on the
  reduced scope only; the artifact must say so and must not claim full-roster
  dominance soundness, a certificate, or performance credit.
- **Parity Cost Awareness**: audit phase uses rehash-only parity; full corpus
  reruns are triggered only by semantic code changes (escalated first).
- **Edge Cases**: tied central values with differing lower/upper; finalist
  promotion ordering; fallback-reason states inside a suffix; signed-zero and
  boundary-bucket contributions mid-suffix; prefix depth 0 (empty partial
  state) and depth 5 (complete team) degenerate cases.
