# X04: Deterministic sharded certificate and verifier

## Acceptance criteria

- [ ] Stable non-overlapping shards emit canonical SHA-256-addressed artifacts
  with scope/kernel hashes, ranges, counts, tie sets, bounds, and runtime data.
- [ ] Reducer reconciliation accounts for every legal team as exact or safely
  pruned by a strictly lower outward-rounded bound.
- [ ] Resumed, serial, and parallel runs produce byte-identical manifests.
- [ ] Winner, complete score tie set, runner-up, gap, and TypeScript replays are
  recorded before the canonical card-ID tie-break.
- [ ] An independent verifier validates hashes, ranges, counts, and reduced proof
  fixtures without trusting the solver process.

## Partial implementation evidence

`pnpm optimizer:shards:verify` runs `scripts/verify-exact-shards.mjs` against
`data/native/exact-optimizer-shard-fixture-v1.json`. It independently checks
canonical SHA-256 addresses, contiguous ranges, scope/kernel identity, and
roster/mechanics/chart hashes, methodology/execution identity, runtime fields,
and exact/pruned reconciliation. A real reduced reference run is generated by
`pnpm optimizer:shards:reduced` and verified with
`pnpm optimizer:shards:verify:reduced`; it covers 56 legal teams in two
contiguous shards, records the complete tie set, runner-up, and micro-unit gap,
and replays its winner against the independent reduced-parity report. Both
artifacts remain explicitly `certificateEligible=false`; the full production
solver still needs compiled mechanic fixtures, resumable shard execution, and
the measured full-scope formulation.

`pnpm optimizer:shards:determinism` additionally proves the canonical reducer
fixture is byte-identical when shard input order is reversed and when the same
shards are presented as a resumed run. This is explicitly a reducer-shape
fixture; it is not evidence that the full production search has completed,
resumed, or parallelized.

`pnpm optimizer:shards:plan` now generates
`data/native/exact-optimizer-full-shard-plan-v1.json`, a canonical plan of 864
contiguous ranges covering all `126,445,821` declared legal Member teams.
`pnpm optimizer:shards:plan:verify` independently recomputes that count,
replays the source hashes, and validates every range and resume token. This is
the full-scope traversal contract only: all shards are marked
`planned-not-evaluated`, all team sets remain unsearched, and the artifact is
not a certificate.

The next proof step is a measured parity-backed aggregation that can safely
reuse chart-specific resolved Leader application graphs. The factorization must
match the TypeScript reference evaluator and reduced brute force before it can
be used by a certifying shard worker.

The first probe is recorded in
`data/native/exact-optimizer-leader-aggregation-benchmark-v1.json`: 32 reduced
teams, two charts, all 113 Leaders, and 1,808 exact lower/central/upper
comparisons with zero mismatches. A deterministic eight-case slice of the
100000-case corpus also covers all Bloom stages and investment layers with zero
mismatches. It reduced representative utility calls by 48.67% in the reduced
sample, but the resolution pass itself is not yet amortized and the result is
explicitly not a full-scope speed claim or certificate.

## Execution handoff

The deterministic 864-shard plan and verifier are complete as a planning
surface, but shard execution is blocked by X05's certifiable performance
architecture. Do not start the planned full run until its factorization gate,
trace-preserving kernel, proof cascade, independent replay evidence, and
cost-model decision have an approved path below the declared budget.
